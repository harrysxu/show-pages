# PaperFlow 全流程交互简化评审

评审日期：2026-10-01。

范围：当前 iOS / iPadOS 原生实现，覆盖导入、文件阅读、页面整理、压缩、OCR、签名与表单、标注、打码、密码保护、页码、水印、批处理、常用流程、结果页和设置。扫描主界面已完成的修订见 [扫描交互修订](./scan-ux.md)。

状态：用户确认后，本轮已完成原生页面与任务逻辑的交互简化，并进行了处理引擎、原生模型和模拟器 UI 回归。HTML 原型尚未同步。下面的问题表、代码行号和第 5 节截图保留为优化前评审基线；当前实现与验证证据见 [交互简化实施记录](./interaction-implementation.md)。模拟器检查不能替代真机验收或首次使用者的可用性测试。

## 1. 优化前的问题

| 优先级 | 现有问题 | 用户受到的影响 | 建议修改 |
| --- | --- | --- | --- |
| P0 | 编辑页顶部分享读取 `sourcePath`，没有生成当前编辑内容 | 屏幕看到的签名、标注、打码标记可能没有出现在分享文件里 | 编辑后的分享先生成当前任务结果；打码必须走永久打码确认与安全处理 |
| P0 | 压缩复制整组 `snapshot.options`；页码、水印页保存流程会开启共享的输出开关 | 单独压缩可能带入用户没有在当前页面选择的页码或水印 | 单工具构建自己的输出选项；组合操作只通过明确的常用流程执行 |
| P0 | 批处理配置参数跳入单文件工具；批处理导入默认转到阅读页 | 用户需要返回寻找批处理入口，可能误执行单文件导出，新导入文件也没有自动选入批处理 | 参数在批处理内部编辑，导入后返回批处理并选中新增文件 |
| P0 | 整理、编辑和 OCR 的执行按钮位于滚动内容之后 | 页数或内容越多，完成操作越难找到 | 主操作固定在屏幕可见区域，参数与内容独立滚动 |
| P1 | 阅读后的工具入口藏在阅读选项内，文件菜单没有常用处理动作 | 导入后不知道下一步如何签名、压缩或合并 | 阅读工具栏提供清晰的处理入口，自动携带当前文档 |
| P1 | 新建签名仅存入签名库，仍需额外选择放置；签名入口重复 | 用户以为保存签名就已完成签署，也可能重复放置 | 在签署任务中创建或选取签名后，直接放到当前页并进入移动状态 |
| P1 | OCR 结果同时铺开全部页面文本，三个导出按钮在最末尾 | 长文档需要大量滚动，技术指标干扰普通用户 | 先选识别目的，结果按页查看；固定复制或生成 PDF 操作 |
| P1 | 页码、水印、保护和流程编辑首屏参数偏多 | 用户需要理解字号、角度、权限、命名变量等概念 | 给出完整默认值，首屏只保留与当前任务直接相关的选择 |
| P1 | iPad 属性列中的开关右侧被裁切 | 开关状态显示不完整，降低可操作性 | 使用系统控件的实际布局尺寸，移除造成裁切的缩放与窄宽度限制 |
| P1 | 流程中的“下一步”与每个工具自己的导出按钮同时存在 | 用户不清楚应该进入下一步还是提前导出 | 流程模式统一使用下一步，最后一步生成结果 |
| P2 | 结果页有多组后续按钮，“继续处理”实际上固定进入签名 | 完成后还要理解多个出口，名称与行为不一致 | 保存、分享为主要出口，其余动作进入明确的菜单 |
| P2 | 首页重复入口，iPad 侧栏一次呈现全部工具与设置 | 初次使用的任务选择负担较高 | 首页突出导入、扫描和最近任务，侧栏分组按需展开 |

### 代码依据

- 顶部分享：`ContentView.swift:64`；`WorkspaceModel.swift:702` 的 `resultURL` 与 `WorkspaceModel.swift:707` 的 `share` 只读取或复制源文件。签名、页面修改和打码区域保存在文档记录中，不能通过复制源文件兑现。已生成结果页分享使用生成文件，不属于同一问题。
- 设置串入压缩：`WorkspaceModel.swift:444`；`EditorPages.swift:125`、`:147` 的保存流程动作会启用共享选项。
- 批处理跳转：`ProcessingPages.swift:124`、`:129`；`WorkspaceModel.swift:341`、`:379` 的普通导入默认进入阅读页。
- 整理按钮：`ProcessingPages.swift:79`、`:90`，工具条和导出按钮位于整个页格之后；编辑导出按钮位于 `EditorPages.swift` 的 inspector 内；OCR 导出位于 `EditorPages.swift:306`，在所有页面的文字编辑器之后。
- 签名保存与放置：`WorkspaceModel.swift:515`、`:519`；保存动作不调用 `addAnnotation`。
- 阅读工具入口：`ModalHost.swift:151`；文件菜单：`DocumentViews.swift:46`。
- 流程按钮：`ContentView.swift:120` 的流程进度条与各页面原有导出动作同时呈现。
- 属性开关：`Theme.swift:131` 的系统 Toggle 被缩放并限制在 40 点宽度中；iPad 签名与水印截图可见右侧裁切。
- 结果页出口：`ModalHost.swift:313`、`:317`；通用“继续处理”实际进入 `.sign`。

以上 P0 是行为或任务路径问题，应先于装饰与视觉微调处理。

## 2. 统一交互规则

1. 每个页面有一个明确的主命令，例如“压缩”“生成 PDF”“完成签署”。保存和分享可以作为结果页的两个直接出口。
2. 默认参数足以完成常用任务。只有水印内容、密码等必要输入需要用户填写，文件名自动生成。
3. 主命令不随长文档、参数展开或键盘出现而失去可达性；横屏、小屏和分屏同样适用。
4. 高级设置按用途归组，通过菜单或选项面板打开。选择后显示当前设置摘要，避免隐藏正在生效的特殊选项。
5. 设置属于具体工具。跨文件复用的用户偏好明确记忆；单次页码范围、选择状态和其他工具的启用开关不会串入下一项任务。
6. 返回恢复进入前的任务、文档、页面位置和选择状态。关闭子面板回到父面板；取消导入清理待执行上下文。
7. 删除、清除工作空间、永久打码和移除密码保留必要确认。旋转、排序等可撤销编辑使用撤销入口，避免多次确认同一操作。
8. 加密默认只改变加密状态。清理元数据、隐藏批注和附件属于独立选择；启用时明确显示将移除的内容。
9. Pro 工具在进入前有明确权益标识，免费额度在相关任务中可见。处理中不出现购买跳转，取消购买保留原任务。
10. iPhone 使用触控可达的工具栏；iPad 可使用预览与属性并排。两端操作顺序与默认值一致。

“选择文件 → 完成处理 → 保存或分享”是三个任务阶段，不意味着包括系统文件选择、手写、逐页核对等动作在内的所有任务都只能点击三次。

## 3. 各功能的建议路径

### 3.1 首页、导入与文件

- 首页首屏突出导入文件、扫描文档、继续未完成任务和最近文件。
- 保留签名、压缩、合并 / 拆分的快速入口。扫描不需要在同一内容区域重复出现两组等权入口。
- 常用流程放在基础任务之后；用户创建或使用后再提高展示权重。
- 示例文件作为独立体验入口。初次点击签名或压缩时不默默把示例设为用户输入；明确选择文件，或者由用户主动进入示例。
- 从工具页开始导入，完成后进入所选工具；从批处理开始导入，完成后返回批处理；从文件页导入，完成后打开文件。
- 关闭选择文件、取消系统文件选择或解锁弹层后，待执行的工具 / 流程上下文不能影响下一次无关导入。
- 文件列表保持搜索、筛选和排序。文件的更多菜单增加签名、压缩及页面处理等常用动作，携带该文件直接进入工具。

### 3.2 阅读

普通阅读页已有较清晰的正文、翻页、缩略图和搜索结构，可延续。

- 让用户直接看到“处理”入口，打开签名、压缩、整理等命令；阅读外观设置继续放在阅读选项中。
- 分享未编辑文件可以直接打开系统分享；分享工作副本要先生成与当前内容一致的文件。
- 阅读选项优先呈现阅读模式、适应宽度和背景。数值缩放、对比度等选项收在第二层，原生双指缩放继续保留。
- 当前页面已存在修改时，呈现工作副本状态；原件与生成副本可区分。

### 3.3 压缩

建议路径：选择 PDF → 默认平衡压缩或调整档位 → 查看结果 → 保存 / 分享。

- 现有轻度、平衡、强力预设与固定压缩按钮可保留，默认平衡且保留原生文字。
- “限制文件大小”改为可选的任务要求，开启后才输入 MB；日常压缩无需填写数字。
- 质量、DPI、灰度 / 黑白、元数据等继续放在高级选项，避免改成一屏完整参数表。
- 明确显示当前特殊设置和会丢失文字搜索能力的选择。
- **实现必须同步改变处理语义。** 当前 `targetMB` 默认 1.5，引擎会为了达到目标逐轮降低图像质量和 DPI（`ProcessingEngine.swift:589`）。仅隐藏输入框仍会强制追求 1.5 MB。关闭大小限制时应按所选档位处理；开启后才尝试达到指定大小。
- 达不到用户指定大小时，保留可用结果，并提供直接调整档位的入口；不要要求重新导入。
- 估算比原文件大时，不用成功色强调增加的比例；显示当前文件已经较小的状态，最终以实际处理结果为准。

### 3.4 页面整理、合并与拆分

建议路径：选择 / 排序页面 → 执行所需操作 → 完成并生成结果。

- 缩略图是页面主体。选择后出现固定操作条，优先展示旋转、提取、删除，其余放入更多菜单。
- 合并、插入和拆分使用清晰入口；普通合并任务可以直接选多个文件、核对顺序并生成结果。
- 批量旋转不再要求点击每张缩略图下的小图标；保留拖动排序，并提供可访问的移动命令。
- 当前缩略图按钮组使用 `scaleEffect(0.7)`（`ProcessingPages.swift:86`）。修订后需实测实际触控区域，保证常用命令至少 44 × 44 点，且相邻命令不重叠。
- 全选、反选、范围选择、倒序放在选择菜单；撤销保持可见。
- 指定范围的拆分提供页面选择或起止页输入，生成分组预览。`1-3,5` 一类表达式作为高级输入能力保留。
- 合并后的顺序清晰可见，不要求用户理解当前文件是默认排在第一位的规则。
- 完成按钮固定；没有改动时不诱导生成重复副本。提取与拆分成功后进入统一结果出口。

### 3.5 签名、填写表单与标注

建议路径：打开 PDF → 创建 / 选择签名并移动到位置 → 完成签署 → 保存 / 分享。

- 签名页默认只呈现文档、签名入口、撤销和固定完成按钮。填写表单与标注通过模式切换继续保留。
- 在签署任务中，新签名保存后直接放到当前页；从资料管理创建签名时仅保存到库，不放到无关文档。
- 已有签名一键放置，放置后自动回到选择 / 移动状态。删除、复制、旋转、应用到其他页等操作在选中签名后出现。
- 创建手写签名使用默认笔色和线宽，撤销 / 清除可见，样式设置作为选项保留。
- 导出默认固定签名；可编辑标注等输出行为放入导出选项，并显示当前状态。
- PDF 含原生表单时，直接显示可填写字段；常用姓名、电话、公司资料作为自动填充选项。普通 PDF 使用自由文本放置，避免让“填写表单”默认等同于填写三项个人资料。
- 标注模式只显示与当前工具相关的颜色、字号或线宽。例如文本需要字号，高亮无需同时调整文本字号。
- 已放置内容列表改为按需打开的管理面板，避免多页签名列表把完成按钮推到页面底部。

### 3.6 OCR

建议路径：选择识别目的 → 开始识别 → 使用结果。

- 目的分为“生成可搜索 PDF”和“提取文字”，默认中文 + English，可更换语言。
- 可搜索 PDF 路径自动完成识别与输出；复核文字可以主动进入，不强制打开每页文字编辑器。
- 提取文字路径以结果为主体，固定显示复制按钮；TXT、Markdown 和 PDF 放在导出菜单。
- 长文档按页查看识别文字，支持页码切换、全文复制、搜索和修改，保留低置信度提示。
- “Vision 识别页”“原生文字页”属于处理详情，首屏只显示识别状态与页数。
- 识别与输出连续执行时仍只算一次 OCR；取消、失败与已有识别结果复用的额度语义需明确验证。

### 3.7 页码与水印

| 工具 | 首屏保留 | 默认行为 | 第二层设置 |
| --- | --- | --- | --- |
| 页码 | 预览、位置、跳过封面、完成按钮 | 从 1 开始，底部居中，全部页面 | 起始编号、前后缀、字体、字号、边距、颜色、奇偶镜像、自定义范围 |
| 水印 | 内容或图片、样式预览、完成按钮 | 适中透明度，全部页面 | 透明度、角度、尺寸、颜色、平铺、前后层、指定范围 |

- 保存为流程放在更多菜单或结果页；不与完成任务的主按钮竞争。
- 应用范围始终有可读摘要，自定义范围启用后显示具体页码。
- 水印可提供办公常用文字，但不替用户决定实际用途；用户填写的内容与预览必须一致。
- 单独执行页码或水印，不自动触发其他输出操作。

### 3.8 永久打码与密码保护

- 打码首屏保留区域选择、查找文字、撤销和固定应用按钮；自由区域、遮挡颜色等放在选项中。
- 文字匹配有结果数和逐项定位，用户可核对、取消个别匹配，再确认永久打码。
- 应用前保留一次明确确认，说明输出不可恢复及原件保留。任何分享出口都不能跳过安全重建。
- 加密码首屏只需要密码、再次确认和加密按钮。文档权限、所有者密码、隐私清理放在独立选项，当前生效行为有摘要。
- 加密不应默认删除附件或批注。现有 `SecurityOptions` 的清理默认值为 `true`（`Models.swift:349`），需要连同默认行为一起重新审查。
- 移除密码使用已解锁会话，能可靠验证时避免再次要求输入同一个密码；仍保留移除保护的确认。
- 密码遗失无法找回、权限依赖阅读器等必要信息继续保留。

### 3.9 批处理与常用流程

批处理建议路径：选择任务 → 选择文件 → 开始 → 保存全部结果。

- 任务与设置摘要位于文件列表上方；开始按钮固定，显示文件数量。
- 参数配置在当前批处理面板内完成，使用相同的参数控件，但不出现单文件执行 / 导出按钮。
- 文件命名默认自动生成，命名规则作为可选设置；显示实际文件名样例，不让用户先学习变量语法。
- 运行后优先展示进度、成功 / 失败数量。保留逐项结果、重试、跳过和暂停 / 继续能力。
- 多文件合并提供明确排序。当前 `batchSelected` 是集合，运行时按工作空间数组取文件（`WorkspaceModel.swift:726`），选择顺序不能被当作合并顺序。
- 导入后留在批处理，自动选中新增文件；失败重试沿用原任务参数。

常用流程建议路径：选择流程 → 确认输入 → 完成人工步骤 → 自动生成结果。

- 普通用户可在任务成功后保存当前流程，只需填写名称。
- 修改流程时按步骤展示，点进单一步骤编辑参数；其他步骤与输出设置折叠。
- 自动操作连续执行；签名、页面选择和必要复核才需要人工参与。
- 流程模式每一步只有下一步 / 最后完成这一条主要路径，避免同时显示工具自己的独立导出按钮。
- 暂停后返回首页显示流程进度；取消流程是独立命令。不能仅导航到首页却继续显示一个似乎仍在运行的进度条。

### 3.10 结果页、设置与快捷指令

- 结果页先呈现生成文件、必要警告和预览；保存到文件、分享直接可达。
- 重命名、前后比较、打开、新窗口、继续处理、保存流程统一收在明确的次级入口。
- 继续处理打开工具选择，并携带新生成的文件，不再固定进入签名。
- 使用默认导出位置后显示保存成功状态与目的地；取消系统保存不会错误显示“已保存”。本机工作副本与系统导出副本状态分别表达。
- 设置按外观、处理默认值、保存与隐私、购买与关于分组；清除命令避免与日常设置紧邻，仍保留确认。
- 快捷指令属于高级入口。常用任务直接打开系统动作配置，试运行使用用户明确选择的任务与文件；测试合并不能只修改工作副本却没有输出。
- iPad 侧栏保持工作台、文件、扫描和工具常驻，细分工具按组展开；分屏时沿用紧凑布局。

## 4. 修改顺序与验收

建议分三组完成，全部现有功能保留：

1. 输出与任务上下文：编辑分享、单工具参数隔离、批处理配置与导入返回、结果继续处理、取消待执行状态。
2. 高频任务：整理 / 合并 / 拆分、签名 / 表单、OCR 的固定主命令与默认路径，压缩可选大小限制。
3. 参数与信息层次：页码、水印、保护、常用流程、结果页、首页和 iPad 导航。

验收重点：
