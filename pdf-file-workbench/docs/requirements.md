# PDF 与文件工作台需求文档

## 1. 产品定位

一款仅面向 iPhone 和 iPad 的本地优先 PDF 工具。用户可以在不上传文件的情况下完成扫描、OCR、合并、拆分、压缩、签名、标注、打码和分享。

核心定位：**把一次 PDF 任务在几分钟内完成，而不是提供一个复杂的文件管理器。**

## 2. 产品目标

- 让用户从其他 App 导入文件后，三步以内完成高频任务。
- 默认在设备本地处理文件，不建立自有文件服务器。
- 使用 Apple 原生能力覆盖 iPhone 和 iPad，并针对触控、Apple Pencil、多任务和分屏布局优化。
- 建立清晰的免费体验和 Pro 付费边界。
- 通过中文办公场景和隐私体验与 Adobe Acrobat、PDF Expert、Scanner Pro 等产品区分。

### 产品决策

我们不做另一个功能数量更多的通用 PDF 编辑器。竞品研究表明，用户愿意为可靠完成文件任务付费，但对强制订阅、基础功能付费墙、复杂界面和升级后权益变化非常敏感。

因此，首版聚焦“扫描、签名、压缩、合并/拆分、导入文件”五个任务入口，并遵循以下原则：

- 原文件默认不修改，结果另存为新文件。
- 处理前显示页数、文件大小和预计输出大小。
- 处理过程中不弹出销售页面。
- 导出真实文件，不能只提供云链接。
- 不要求账号，不上传用户文件。

详细竞品数据、用户评价、价格观察和取舍依据见 [竞品分析](./competitive-analysis.md)。

## 3. 目标用户

### 主要用户

- 经常处理合同、报销单、证件和申请材料的办公用户。
- 需要扫描和签名文件的自由职业者、小商户和学生。
- 习惯使用 iPhone、iPad、iCloud Drive 和 AirDrop 的 Apple 用户。
- 不希望把工作文件上传到第三方云服务的隐私敏感用户。

### 用户需求假设

1. 用户通常是因为一个具体任务打开应用，例如“签名并发出合同”。
2. 用户不愿意为一次简单操作学习复杂界面。
3. 文件隐私和导出质量会直接影响付费意愿。
4. 用户愿意为批处理、无水印、OCR 和自动化付费。
5. 用户更愿意为明确节省时间的结果付费，而不是为功能数量付费。
6. 系统文件工具和免费竞品会压低阅读、基础标注和简单签名的付费空间。

## 4. 功能优先级

### P0：首版必须实现

- 从 Files、照片库、相机和 Share Extension 导入文件。
- 扫描纸质文件并生成多页 PDF。
- 本地 OCR，支持中文和英文。
- PDF 合并、拆分、旋转和页面重排。
- PDF 压缩，并显示压缩前后的文件大小。
- 手写或图片签名，支持重复使用签名。
- 标注、下划线、文本框和形状。
- 通过 Files、AirDrop、邮件和其他分享目标导出。
- StoreKit 2 购买、恢复购买和家庭共享。

### P1：验证后实现

- 敏感内容永久打码，并验证复制、搜索和文本提取都无法恢复原文。
- PDF 密码保护和密码移除。
- 批量压缩、合并和重命名。
- 页面编号、水印和可复用文档模板。
- Shortcuts 批处理和 iPad 快速操作。
- iPad 拖放和 Apple Pencil 深度工作流。

### P2：暂缓

- 自有云盘和账号系统。
- 在线协作和多人批注。
- PDF 任意已有文本和图片编辑。
- 复杂的 Word/Excel/PPT 高保真转换。
- AI 摘要、问答、翻译和语音功能。
- 依赖服务器的 OCR 或文件转换。

## 5. 核心用户流程

### 流程 A：扫描并发送

1. 用户打开应用并选择“扫描”。
2. 相机自动识别页面边缘并拍摄。
3. 用户调整页面顺序和裁剪范围。
4. 应用生成 PDF 并执行本地 OCR。
5. 用户选择分享、保存到 Files 或签名后导出。

### 流程 B：处理已有 PDF

1. 用户从 Files 或 Share Sheet 导入 PDF。
2. 首页展示“合并/拆分、压缩、签名”三个高频处理操作；打码在 P1 阶段加入。
3. 用户完成操作并预览结果。
4. 用户导出文件，原文件保持不变。

## 6. Apple 生态方案

- SwiftUI：统一实现 iPhone 和 iPad 界面，根据屏幕尺寸适配单栏与分栏布局。
- PDFKit：PDF 阅读、页面操作和基础标注。
- Vision：设备端文字识别。
- VisionKit：文档扫描。
- Files / File Provider：访问本地文件和 iCloud Drive。
- Share Extension：从邮件、微信、Safari 等应用直接导入。
- App Intents / Shortcuts：批量压缩、合并和生成报告。
- Apple Pencil：iPad 上进行签名和标注。
- StoreKit 2：Pro 购买和恢复购买。
- SwiftData：保存最近文件、签名和用户设置。

## 7. 与竞品的差异

### 竞品优点

- PDF Expert：产品成熟，阅读和编辑体验完整。
- Adobe Acrobat：品牌强，跨平台能力强。
- Scanner Pro：扫描体验好，适合快速数字化纸张。

### 产品切入点

- 默认本地处理，首页明确展示“文件不会上传”。
- 针对中文合同、报销和证件材料设计快捷流程。
- 用户可以不订阅就完成一次完整任务。
- 打码结果必须真正删除敏感内容，不能只是盖一层黑色图形。
- 通过 Shortcuts 和 Share Extension 减少文件来回切换。
- 首屏展示任务入口，而不是复杂的工具墙。

### 竞品验证出的付费信号

- PDF Expert、Adobe Acrobat、Scanner Pro 和 iLovePDF 都通过高级编辑、OCR、转换、压缩、同步或批处理收费，说明办公文件处理存在真实付费需求。
- PDFgear 的商店文案主张全部功能免费，说明阅读、基础标注和简单页面操作不能直接作为我们的主要收费点。
- 公开评价集中抱怨订阅提示、基本功能锁定、界面改版、扫描质量回退和旧买断权益变化。

### 我们可以超过的范围

我们短期不能超过 Adobe 的企业生态、格式兼容性和 AI 规模，也不能在首版超过 PDF Expert 的功能数量或 Scanner Pro 多年积累的扫描成熟度。

我们可以在以下窄范围建立优势：

- 本地优先和权限透明。
- 中文合同、报销、证件和申请材料流程。
- 无账号、无云上传、直接导出附件。
- 一个任务一条清晰路径，减少菜单和弹窗。
- 更完整地使用 Files、Share Extension、Shortcuts、Apple Pencil 和 iPad 拖放。
- 买断优先、价格透明，不使用默认周订阅。

## 8. 付费方案

### 免费版

- 查看和分享 PDF。
- 每月有限次数的扫描和 OCR。
- 基础标注。

### Pro 版

- 无限 OCR、扫描、压缩和批处理。
- 无水印导出。
- 高级签名和打码。
- Shortcuts 自动化。
- 一次性买断建议价格：¥48–98。

免费用户必须能够完整完成至少一次核心任务。Pro 付费墙应在用户看到任务结果或继续批量处理时出现，不能在打开应用或扫描过程中打断用户。

早期优先测试一次性买断。如果后续提供持续更新的转换、同步或报告服务，再增加年订阅。具体价格在 TestFlight 验证后根据购买意愿和留存调整。

## 9. 隐私与审核要求

- 文件默认只写入用户选择的本地位置或 iCloud Drive。
- 相机、照片和文件权限必须逐项说明用途。
- 不读取与当前任务无关的文件。
- 所有删除和覆盖操作必须经过明确确认。
- 隐私政策、Privacy Manifest 和 App Store 数据声明必须与实际行为一致。

## 10. MVP 验收标准

- 新用户在首次打开后 60 秒内可以导入或扫描文件。
- 一份 10 页以内的 PDF 可以在设备端完成 OCR。
- 合并、拆分、压缩和签名后的 PDF 能在系统预览和常见 PDF 阅读器中正常打开。
- 在无自建服务器的情况下可以完成完整核心流程。
- 购买、恢复购买和卸载重装后的权益恢复正常。

P1 永久打码上线后，必须额外验证被遮盖的文本无法通过复制、搜索或文本提取恢复；该能力不作为 P0 发布阻塞项。

## 11. 市场验证标准

在开发 P1 功能前，用真实设备和 30–50 名目标用户进行 TestFlight 验证，至少覆盖以下任务：

1. 扫描 5 页中文合同，生成可搜索 PDF 并分享。
2. 从 Files 导入 PDF，签名后通过邮件发送附件。
3. 将大 PDF 压缩到指定大小并保持页面可读。

记录以下指标：

- 首次打开到完成第一个任务的时间。
- 任务成功率和需要帮助的步骤。
- OCR 错误率、扫描裁切错误率和导出失败率。
- 用户是否主动完成第二次任务。
- 看到 Pro 权益后愿意支付的比例。
- 用户对买断、年订阅和免费限制的选择。

只有当核心任务成功率、稳定性和付费意愿达到目标，才开始开发永久打码、密码保护和批处理。

## 12. 后续版本

- 文档模板和最近任务。
- 批量重命名和批量压缩。
- OCR 结果编辑和搜索。
- iPad 快捷操作与多窗口工作流。
- PDF 表单填写。
- 与 Apple Pencil 更深度的签名工作流。
