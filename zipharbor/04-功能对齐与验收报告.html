ZipHarbor 功能对齐与验收报告

验收日期：2026-09-30
工程目录：app/
Bundle ID：com.xiaolongxu.zipharbor
原型基线：app-prototype.html

1. 结论

原生 App 已完成一次 UI/UX 重构，核心结构已经按 HTML 原型对齐。当前页面不再使用旧版系统 TabView、系统大标题、List/Form 组合，而是采用原型中的自定义顶栏、渐变欢迎卡、双列快捷操作、圆角内容区和胶囊底部导航。

这不是逐像素复制：原型使用演示数据和网页图标，原生 App 使用真实 Files/Photos 入口、SwiftUI 原生控件和动态数据。核心信息层级、主操作入口、页面导航和任务筛选逻辑已对齐，具体字体渲染、系统弹窗和文件选择器仍由 iOS 决定。

密码解压问题修复

此前 libarchive 在真正读取加密 ZIP 文件内容时返回 Passphrase required for this entry，应用将其误判为损坏压缩包并直接显示错误。当前已统一映射为需要密码/密码错误状态，解压会重新打开密码输入弹窗；修复后的模拟器单测 8/8、UI 测试 1/1 通过，结果包：

  • 单测：/tmp/ZipHarbor-password-fix-sim2/Logs/Test/Test-ZipHarbor-2026.09.30_22-14-43-+0800.xcresult
  • UI 测试：/tmp/ZipHarbor-password-fix-full/Logs/Test/Test-ZipHarbor-2026.09.30_22-15-16-+0800.xcresult
  • 修复版真机截图：iphone14-real-password-fix.png

本轮交互修复：从解压动作触发密码输入时，输入正确密码后会自动继续当前解压任务，不再要求再次点击“解压到…”；解压完成页的“完成”按钮现在会关闭结果弹窗。修复后模拟器全量测试 8/8 单测、1/1 UI 测试通过，真机修复版已重新安装，并通过 devicectl device process launch --console 验证应用进程可正常启动。

6. 已知边界

  1. 当前使用的 libarchive.xcframework 7z 写入器不提供 7z AES 创建能力；应用已在逻辑层和 UI 层明确禁止该组合，ZIP AES 仍可用。
  2. ZIP 分卷使用 ZipHarbor 的 .zip.001 原始切片卷组，ZipHarbor 内可导入和解压，其他工具是否识别取决于其卷格式支持。
  3. 暂停后检查点恢复、本地通知、Shortcuts、回收站、云端 File Provider 下载等待、逐文件冲突询问、空间预检和完整校验仍需后续补齐。
  4. RAR 以读取为主，加密 RAR 明确提示不支持；发布前仍需使用真实 RAR4/RAR5 样本做跨工具兼容性验证。

7. 发布前动作

  • 在真机 UI 自动化环境稳定后补跑页面断言；当前已完成真机安装、启动和核心归档单测。
  • 使用真实 ZIP AES、RAR4/RAR5、7z 样本和 ZIP 分卷 fixture 做跨工具兼容测试。
  • 完成空间检查、特殊文件拒绝、完整校验、暂停/恢复和通知后再提交 App Store。
